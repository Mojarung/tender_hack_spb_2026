# Что мы строим (PriceFinder для Портала поставщиков)

Кодовое имя проекта: **PricePulse**.

Это структурированный «продуктовый срез» технического задания (см. [tz.md](./tz.md)) — то, что должно быть на финальной защите 24.05.2026. Источник истины — `tz.md`, раздел V и пункты VII.7.

---

## 1. Цель продукта

Веб-сервис, по запросу пользователя Портала поставщиков ([zakupki.mos.ru](https://zakupki.mos.ru/)) **в режиме почти-реального времени** агрегирующий цены товара из нескольких открытых источников Рунета и показывающий **сводку по источникам** + **детализацию по предложениям** со ссылками на оригинал.

## 2. Обязательные фичи (MUST из ТЗ, V.5.1)

Контрольный список — каждый пункт обязан быть закрыт.

### 2.1 Источники данных
- [ ] **Яндекс Маркет** — обязательный источник.
- [ ] **Ozon** — обязательный источник.
- [ ] **Wildberries** — обязательный источник.
- [ ] **Минимум один «неформализованный» источник Рунета**, который **не зафиксирован** — выбирается динамически по поисковому запросу (например, через SearXNG/Firecrawl-search). Можно подключать произвольное число таких источников.
- [ ] Используются **только бесплатные** инструменты для неформализованного поиска (никаких платных API типа SerpAPI/BrightData — кроме как опционально).

### 2.2 Карточка предложения (минимальный набор полей)
По каждой найденной товарной позиции пользователь видит:
- [ ] Изображение
- [ ] Наименование
- [ ] Характеристики (как они представлены источником; нормализация — best-effort)
- [ ] Цена
- [ ] Ссылка на источник (deep-link на конкретную карточку/предложение)

### 2.3 Группировка
- [ ] Результаты сгруппированы по источникам: «на Яндекс Маркете найдено N предложений от X ₽, на Wildberries — M предложений от Y ₽, в прочих источниках Рунета — K предложений от Z ₽».
- [ ] Для каждой группы — счётчик предложений и минимальная/средняя/медианная цена (минимум — минимум).

### 2.4 Качество поиска
- [ ] **Исправление опечаток** в запросе (russian-aware).
- [ ] **Синонимы** (брендовые/категорийные/жаргонные) — увеличивают релевантность выдачи.
- [ ] Нормализация запроса (лемматизация / morphology) перед обращением к источникам.

### 2.5 Устойчивость и обход ограничений
- [ ] **Антибот / обход rate-limit** — обоснованная стратегия (прокси-ротация, fingerprinting, отложенный retry, кэш). См. [backend/ARCHITECTURE.md](./backend/ARCHITECTURE.md), раздел про anti-bot.
- [ ] Не падать при недоступности любого одного источника — graceful degradation.

### 2.6 UI/UX
- [ ] Удобный, интуитивно понятный веб-интерфейс.
- [ ] Один основной экран: ввод запроса → стриминг результатов по мере прихода ответов от источников (без «зависшего» спиннера на 30 с).
- [ ] Видны badges/счётчики по источникам и список карточек.

### 2.7 Нефункциональные
- [ ] **Тестирование на реальных кейсах** — подобрать 10–15 тестовых запросов разной сложности, прогнать перед защитой.
- [ ] **Масштабируемость** — горизонтальное масштабирование воркеров скрейпинга, изолированные адаптеры по источникам, очередь.
- [ ] **Демонстрация работоспособности** — рабочее демо на площадке.
- [ ] **BPMN-схема** — диаграмма потока обработки запроса (одна страница, экспорт PDF/SVG, кладём в `docs/bpmn.svg`).

### 2.8 Free-mode по умолчанию

- [ ] **Никаких платежей по дефолту** — `FEATURES_ALLOW_PAID=false` killswitch
- [ ] **Oracle Cloud Free Tier** как proxy-пул (4 ARM cores + 24 GB RAM forever free)
- [ ] **Gemma 4** локально через Ollama для CAPTCHA и LLM-extract (вместо платных Gemini/2Captcha)
- [ ] **OpenCV slider-solver** — бесплатный, без LLM, WR ≥95% на Ozon slider
- [ ] **Демо-режим** — прогрев Redis-кэша по 15 жюри-запросам, <100 ms ответ
- [ ] **Все платные сервисы** включаются гранулярными флагами (`FEATURE_USE_2CAPTCHA`, etc.) — никаких сюрпризов в счёте

Полный документ: [backend/docs/free-mode.md](./backend/docs/free-mode.md).

### 2.9 Сверх-ТЗ: что добавляем для wow-эффекта на защите

- [ ] **История цен в карточке** (sparkline) — для WB через публичный `wbx-content-v2.wbstatic.net/price-history`, для остальных — наш сбор за время хакатона.
- [ ] **Sentiment-анализ отзывов** — `seara/rubert-tiny2-russian-sentiment` (3 ms/text на CPU), badge positive/neutral/negative.
- [ ] **Best-Deal Score** — формула с UI-слайдерами весов, чтобы жюри могло «покрутить» прямо на демо.
- [ ] **MinIO image cache** — отдаём картинки из своего S3, чтобы UI не моргал при ребрендинге basket-CDN.
- [ ] **Prometheus + Grafana** — live-дашборд «Live Scraping» с метриками RPS / success rate / капчи / стоимость на 1000 запросов.
- [ ] **n8n** — визуальный live-view парсинга + Telegram-алерты + auto-fallback workflow.
- [ ] **Cost guard** — hard-cap $50/24ч с автоматическим отключением платных слоёв при превышении.

## 4. Чего НЕТ в ТЗ — и потому не делаем

Чтобы не растащить скоуп:

- ❌ Авторизация пользователей / личные кабинеты — в ТЗ не требуется.
- ❌ Сохранение истории по пользователю — не требуется (можно cache по запросу — это другое).
- ❌ Закупочные процедуры, интеграция с zakupki.mos.ru на запись — мы только источник данных «снаружи».
- ❌ Платные API источников (Wildberries Seller API, Ozon Seller API) — они требуют токенов конкретного селлера и **не дают доступа к чужим ценам**. Это ловушка — не идём туда.
- ❌ Мобильное приложение — только веб.

## 5. Риски и митигации

| Риск | Митигация |
|---|---|
| Yandex SmartCaptcha на Маркете | Camoufox + warm `spravka` cookies + RU residential + 2captcha (рубли); кэш 6 ч |
| Ozon Cloudflare + slider | Mobile composer-api с `ozonapp_android` UA через curl_cffi → Patchright fallback |
| WB временные блокировки IP | `httpx.http2=True` без прокси для <5 RPS; curl_cffi(chrome131) + DC proxy при 429 |
| Полная блокировка одного источника | Cascade L1→L2→L3→L4; circuit-breaker; кэш Redis + MinIO; никогда не валит запрос целиком |
| Превышение бюджета на капчи/прокси | Cost guard $50/24ч; Prometheus counter; авто-disable L3+L4 при превышении |
| Долгий «холодный» запрос (10+ сек) | SSE streaming; первые карточки приходят за 1–2 с из Redis-кэша |
| Дисквалификация по п. 7.5 (проект создан НЕ на хакатоне) | Этот репозиторий — только инфраструктура: Dockerfile, ARCHITECTURE.md, anti-bot.md, конфиги. Вся доменная логика пишется в окне 22.05 21:00 — 25.05 13:00. |

## 6. Definition of Done (на каждый из 4 источников)

Источник считается «готовым», когда:
1. Скрейпер реализует `ScraperProtocol` (см. `backend/src/pricepulse/scrapers/base.py`).
2. По запросу «iPhone 15 128 ГБ» возвращает ≥3 валидных предложения с заполненными обязательными полями (см. 2.2).
3. Покрыт smoke-тестом, который ходит на источник (помечен `@pytest.mark.live`).
4. Имеет fallback при блокировке (не падает, возвращает пустой результат + метрику).
5. Стратегия rate-limit описана в коде комментарием со ссылкой на источник.
